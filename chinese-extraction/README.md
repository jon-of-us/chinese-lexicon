# chinese-extraction guide

> **Legacy.** The app no longer reads this pipeline's output. It reads [chinese-dataset/](../chinese-dataset/), which is maintained by hand and kept locally. The paths below point at the `chinese/` folder, which is kept for now. The scripts write there, so they must be updated before they run again.

This directory previously generated the data the app used: it downloaded raw data, built frequency lists, and converted sentences from each source into the app's format. Outputs went to the `chinese/` directory at the repository root. For the overall picture, see [CHINESE_OVERVIEW.md](../CHINESE_OVERVIEW.md).

**Run all commands from the repository root.**

## Directory structure

```
chinese-extraction/
├── migrations/                 Python: converts each source into the unified sentence JSON (see migrations/README.md)
│   ├── common.py               Shared logic: segmentation, translation, output writing, reports
│   ├── migrate_all.py          Runs all migrations in order
│   ├── migrate_hsk_sentences_audio.py
│   ├── migrate_tatoeba.py
│   └── migrate_anki_tatoeba.py
├── build_media_frequency_lists.mjs   Node: generates media word and character frequency lists
├── build_tatoeba_hsk13.mjs           Node: builds the Tatoeba HSK 1–3 sentence TSV
├── download_hf_audio.sh              Shell: fills in HSK sentence audio (Git LFS)
├── download_hsk_word_audio.sh        Shell: fetches native-speaker HSK word and syllable pronunciations
├── requirements.txt                  Python dependency: spacy-pkuseg==1.0.1
├── hsk-sentences-audio/              Git submodule: HSK sentence dataset
├── tatoeba/                          Raw Tatoeba exports and audio (see tatoeba/README.md)
├── anki/                             Anki package and the unpacked collection and media
└── migration-reports/                Run report for each migration source (JSON)
```

## Run flow

```bash
# 1. Fetch audio (optional, but needed by migrations and the app)
bash chinese-extraction/download_hsk_word_audio.sh     # native-speaker word/syllable audio → chinese/audio-cmn/
bash chinese-extraction/download_hf_audio.sh           # LFS pointers for HSK sentence audio

# 2. Build the Tatoeba HSK 1–3 TSV
node chinese-extraction/build_tatoeba_hsk13.mjs

# 3. Generate sentence JSON and audio
pip install -r chinese-extraction/requirements.txt
python3 chinese-extraction/migrations/migrate_all.py   # → chinese/sentences/*.json, chinese/sentence-audio/

# 4. Generate media frequency lists
node chinese-extraction/build_media_frequency_lists.mjs  # → chinese/media-frequency-{words,characters}.json
```

Migration output is `chinese/sentences/<source>.json` and `chinese-extraction/migration-reports/<source>.json`. The app statically imports the first three JSON files at build time, so **they must exist**.

## Script notes

- **build_media_frequency_lists.mjs**: takes the top 2000 words by media rank from `allEntries` in `chinese/dong-chinese` and generates the character frequency list. The paths are correct.
- **build_tatoeba_hsk13.mjs**: reads the Chinese and English sentence exports (bz2) from `tatoeba/`, labels words with HSK levels using `getHSKLevel` from `dong-chinese/statistics/hsk.js`, keeps sentences at levels 1–3, and writes `tatoeba/hsk1-3_cmn_eng_audio.tsv`.
- **download_hsk_word_audio.sh**: sparse-clones `hugolpz/audio-cmn` and syncs `96k/hsk` and `64k/syllabs` into `chinese/audio-cmn/`. Licensed CC BY-SA 4.0, see [ATTRIBUTION.md](../chinese/audio-cmn/ATTRIBUTION.md).
- **download_hf_audio.sh**: replaces LFS pointers with real mp3 files and supports resuming.
- **migrations/**: see [migrations/README.md](migrations/README.md) for the unified format and the segmentation and alignment rules.

## Caveats and open decisions

- **Regenerating HSK sentence output**: `migrate_hsk_sentences_audio.py` builds per-word glosses from the working-tree `chinese/dong-chinese/dictionary/cedict.js`, which has uncommitted edits. Regenerating changes 231 records. See [CHINESE_OVERVIEW.md](../CHINESE_OVERVIEW.md) section 7.
- **Resolved**: the Tatoeba raw exports were removed from git history (over GitHub's 100 MB limit). `tatoeba/links.csv` must be downloaded per clone; see [tatoeba/DOWNLOAD.md](tatoeba/DOWNLOAD.md).
